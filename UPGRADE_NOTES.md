# NEUROPIX 2.0 — состояние ветки

## Что уже внесено
- Удалён публичный `GET /tasks/{task_id}`: статус задачи нельзя получить без проверки владельца.
- Ключ идемпотентности ЮKassa стабилен для пары «заказ + способ оплаты», чтобы повтор запроса того же заказа не создавал новый платёж.
- `.env.example` дополнен используемыми переменными; платная генерация по умолчанию выключена.
- Добавлена дедупликация входящих `message_created` от MAX по уникальному `message.body.mid`. Событие считается обработанным только после успешной отправки ответа; зависшая попытка может быть повторена через 5 минут.
- Добавлены повторяемые CI-проверки: установка зависимостей, компиляция Python и unit-тесты.

## Что ещё требует отдельной реализации или проверки
- Восстановление `submission_unknown`: нельзя безопасно повторно создавать задачу, пока GEN202 не предоставляет подтверждённый способ найти уже принятую задачу.
- Фоновая проверка задач и автоматическая доставка готовых медиа в MAX. Сейчас пользователь проверяет статус кнопкой, а результат приходит ссылкой.
- Интеграционные тесты с реальными тестовыми окружениями MAX, YooKassa и GEN202.
- Проверка миграций и конкурентных сценариев на отдельной тестовой PostgreSQL.
- Проверка полного набора переменных Render и актуальных webhook URL перед запуском.

## Безопасность запуска
- `ENABLE_PAID_GENERATION=false` — оставить выключенным до отдельного разрешения владельца и завершения интеграционных тестов.
- Не проводить реальные платежи и платные запросы GEN202 в CI.
- Изменения находятся в ветке `neuropix-2.0`; `main` не изменяется автоматически.
- Не выполнять production-деплой до проверки настроек Render и подтверждения владельца.

## Проверка
CI запускает:
1. `python -m py_compile main.py gen202.py yookassa.py`
2. `python -m unittest discover -s tests -v`

Перед production-запуском дополнительно нужны интеграционные тесты, проверка webhook-подписей/секретов и ручная проверка платежного сценария в тестовом режиме.
